\begin{abstract}
A drift alarm reports that production data changed, but the right response depends on the type of change, which monitoring tools rarely name. We present an open monitoring pipeline whose core names four drift types with a stated error rate. Established label free tests separate covariate shift from prior shift. A new test on a few hundred late labels separates concept drift from label noise. On injected drift in two census tasks with two model families, the procedure names the type in \res{bench-a-ours-min} to \res{bench-a-ours-max}\% of windows and beats rules from monitoring practice. A learned classifier does better on the drift it was trained on but reaches only \res{bench-b-meta-min} to \res{bench-b-meta-max}\% on held out drift mechanisms, where our tests keep \res{bench-b-ours-min} to \res{bench-b-ours-max}\%. On four real datasets with documented changes, it reported no drift on any control window and traced the known events.
\end{abstract}

\keywords{data drift, concept drift, label shift, label noise, model monitoring, hypothesis testing, drift diagnosis}

\section{Introduction}
\label{sec:intro}

A deployed classifier can quietly lose accuracy as production data move away from the data it was trained on, often long before reliable labels arrive \cite{rabanser2019failing}. Existing monitors are good at announcing that a distribution has changed \cite{rabanser2019failing} and at estimating how much accuracy was lost \cite{garg2022atc,kivimaki2025performance}. They say little about what kind of change occurred. A drift alarm on its own is not a plan, because each kind of drift calls for a different response.

The literature names three types of dataset shift \cite{moreno2012unifying}. Under covariate shift the inputs move but the rule that links inputs to labels holds, so reweighting the training data can help. Under prior shift only the class balance changes and the model can be recalibrated. Concept drift changes the rule itself and needs fresh labels. We add label noise as a fourth type. It corrupts the labels that judge the model and points to the labelling process rather than to the model.

Naming the type is harder than detecting a change. Covariate and prior shift both move the inputs and the predictions. Concept drift and label noise leave the inputs untouched, so no label free test can see them.

We name the type with a short sequence of hypothesis tests at one significance level, with the family wise error rate controlled. The first stage needs no labels and builds on established methods. It tests the inputs and the predictions for a shift, estimates the new class balance by black box shift estimation (BBSE) \cite{lipton2018bbse} and, like Roschewitz et al. \cite{roschewitz2025shiftid}, asks whether this balance alone explains the shift in the inputs (prior shift) or not (covariate shift). The second stage is new. With a few hundred late labels it asks whether accuracy fell and whether the errors changed in a way that depends on some input feature. Uniform label noise changes the error rate only according to how confident the model is, while concept drift changes it in one region of the inputs. Because every step is a test, the false alarm rate is fixed in advance.

The contributions are as follows.
\begin{enumerate}
\item An audit test that separates concept drift from label noise with a few hundred late labels. Existing shift tests, such as DetectShift \cite{maiapolo2023detectshift}, need labelled production data or ignore label noise.
\item A hierarchical procedure that combines this audit with a label free stage and names four drift types with family wise error control.
\item A benchmark on two tabular tasks and two model families with matched and held out drift mechanisms. It shows that tests built on the definitions of the types transfer to new drift where a learned rule does not.
\item An open end to end monitoring pipeline, from detection and accuracy estimation through root cause analysis and diagnosis to reliability scoring and remediation triage, evaluated on four real drifts with documented causes.
\end{enumerate}

\paragraph{Drift types.} Moreno-Torres et al. define covariate shift, prior shift and concept shift by which part of the joint distribution of inputs and labels changes \cite{moreno2012unifying}. DetectShift tests for a shift in the joint distribution and in each of its parts, $P(X)$, $P(Y)$, $P(X\mid Y)$ and $P(Y\mid X)$ \cite{maiapolo2023detectshift}. It needs labels for the new data, a limitation its authors name themselves. We use the same definitions, add label noise as a fourth type and need labels only for a small audit.

\paragraph{Drift detection.} Detectors that track the error rate, such as the drift detection method (DDM) \cite{gama2004ddm}, need a label for every prediction. They see concept drift but cannot tell it from label noise. Label free detectors compare inputs or model outputs. Rabanser et al. compare univariate tests, kernel tests \cite{gretton2012kernel}, classifier two sample tests \cite{lopezpaz2017c2st} and BBSD on the model outputs. They find that BBSD works best overall \cite{rabanser2019failing}. All of these say that a shift happened, not of which type. Our pipeline uses such tests as building blocks and goes on to name the type.

\paragraph{Label shift.} BBSE recovers a new class prior from the confusion matrix of any classifier \cite{lipton2018bbse}. It assumes that the inputs within each class do not change, which is exactly the assumption that separates prior shift from covariate shift. Roschewitz et al. test this assumption for medical images. They resample the reference to the estimated prevalence and call the shift a prevalence shift if the features no longer differ \cite{roschewitz2025shiftid}. Our label free stage builds on this idea, with importance weights in place of resampling and every label free decision in one family with a stated error rate.

\paragraph{Performance estimation without labels.} Average confidence (AC) \cite{hendrycks2017baseline}, difference of confidences (DoC) \cite{guillory2021predicting}, average thresholded confidence (ATC) \cite{garg2022atc} and CBPE \cite{kivimaki2025performance} estimate accuracy from model outputs. All assume that the link between confidence and accuracy carries over to production. Models often stay confident as accuracy falls under shift \cite{ovadia2019trust}, so this assumption can fail. Our pipeline reports CBPE, compares it with the other three and treats it as an upper bound when the assumption breaks.

\paragraph{Explanation, reliability and benchmarks.} Shapley additive explanations (SHAP) \cite{lundberg2017unified} and class activation maps (CAM) \cite{zhou2016cam} attribute predictions to features or image regions. Out of distribution (OOD) scores such as the Isolation Forest \cite{liu2008isolation} flag unusual inputs. Importance weighting corrects covariate shift \cite{shimodaira2000,sugiyama2007,cortes2010weights}. Folktables \cite{ding2021retiring} and CLEAR \cite{lin2021clear} provide real shifts, but the type of each shift is unknown. Injected shifts give a ground truth \cite{rabanser2019failing}, at the risk of matching the method under test. Our pipeline uses each of these tools in one of its stages. Its benchmark holds out drift mechanisms to limit that risk.

Each prior method covers part of the task. To our knowledge no published method separates concept drift from label noise with a small label audit. None grades a type diagnosis on drift mechanisms held out from its design.

\section{Method}
\label{sec:method}

The pipeline is built for a team that has three things: a deployed model, the labelled data it was built on and a stream of unlabelled production data. Nothing else is required. When a few hundred late labels become available, they sharpen the diagnosis. This section first defines the four drift types and then follows the data through the pipeline.

Stages A to C put the data in a common form, test whether anything changed and estimate how much accuracy the change may cost. Stage D, the core of this paper, names the type of change and points to its likely cause. Stages E and F turn these findings into action for single predictions and for the retraining decision. Only the optional audit in stage D uses production labels. Apart from the population stability index (PSI), which alarms at its usual threshold, every decision is a hypothesis test at the significance level $\alpha=\res{acs-alpha}$. The family wise error rate is controlled by the Holm procedure \cite{holm1979}, its weighted form or its Bonferroni bound.

\subsection{Notation and drift types}
\label{sec:types}
The tests that follow need a precise statement of what each type of drift changes. The reference data are drawn from a distribution $P(X,Y)$ of inputs $X$ and labels $Y$. A production window is a batch of rows from a later period or another region, drawn from $Q(X,Y)$. The model returns a predicted label $\hat y$ and a confidence $c$, its largest class probability. The four types are defined by what changes between $P$ and $Q$. Covariate shift has $Q(X)\neq P(X)$ while $Q(Y\mid X)=P(Y\mid X)$. Prior shift has $Q(Y)\neq P(Y)$ while $Q(X\mid Y)=P(X\mid Y)$. Concept drift has $Q(Y\mid X)\neq P(Y\mid X)$. Under label noise the true distribution is unchanged, but each observed label differs from the true label with some probability. An audit is a random sample of $m$ production rows whose labels arrive late. A control window is drawn from the reference distribution itself, so it should raise no alarm. Real drift can mix types, a point Section~\ref{sec:discussion} returns to.

\subsection{Reference split, detection and estimation}
This stage asks three questions in turn: did the data move, how much accuracy might the change cost and where does it sit? It first needs a clean reference. The labelled reference data are split into three disjoint parts, stratified by class: \res{acs-split-pct-train}\% for training, \res{acs-split-pct-calibration}\% for calibration and \res{acs-split-pct-test}\% for testing. The model is fitted on the training part only. The calibration part is the reference window for every detector and fits the accuracy estimator. The test part gives the reference accuracy and serves as the control window. Nominal features, such as an occupation code, are declared categorical because their numeric order has no meaning. Images are mapped to the \res{clear-dim} dimensional output of the global average pool of a frozen residual network with 18 layers (ResNet-18) trained on ImageNet \cite{he2016deep}. Image drift can then reuse the tabular tests \cite{rabanser2019failing}.

Six detectors decide whether the inputs or the model outputs moved. The Kolmogorov--Smirnov (KS) test runs on each numeric feature, with a Bonferroni correction. PSI alarms at the usual value of \res{acs-psi-threshold} \cite{siddiqi2006}. The maximum mean discrepancy (MMD) test \cite{gretton2012kernel} is a permutation test on all standardized inputs at once, with a Gaussian kernel. The confidence test compares histograms of $c$ with a $\chi^2$ test of homogeneity. It pools sparse cells until every expected count reaches \res{const-min-expected} \cite{cochran1954}. Two detectors from Rabanser et al. serve as baselines \cite{rabanser2019failing}. BBSD runs a KS test on each class probability. The domain classifier learns with gradient boosted trees to tell \res{acs-dc-n} reference rows from as many production rows. Its held out accuracy is compared with $1/2$ by an exact binomial test \cite{lopezpaz2017c2st}. Every permutation p value is given by $(1+b)/(1+B)$, where $b$ of $B$ permutations reach the observed statistic \cite{phipson2010}.

Labels arrive late, so accuracy must first be estimated from the model's own confidence. We use CBPE \cite{kivimaki2025performance}. A map $a(\cdot)$ from confidence to the probability of a correct prediction is fitted by histogram binning on the calibration part. The estimate for a window with confidences $c_1,\dots,c_n$ is given by
\begin{equation}
\widehat{\mathrm{acc}} = \frac{1}{n}\sum_{i=1}^{n} a(c_i).
\label{eq:cbpe}
\end{equation}
A confidence bin with fewer than \res{const-min-expected} calibration rows holds no reliable accuracy, so a prediction in such a bin keeps its own confidence. AC, DoC and ATC with the negative entropy score are fitted on the same calibration part as baselines \cite{hendrycks2017baseline,guillory2021predicting,garg2022atc}.

An alarm is more useful when it says where the change sits. Localization tests every feature with KS (numeric) or $\chi^2$ homogeneity (nominal) under Holm correction. It reports an effect size in $[0,1]$, the KS statistic or Cram\'er's $V$. For nominal features it also gives the share of production rows whose category never occurs in the reference.

\paragraph{Label free stage.} The first question in Figure~\ref{fig:decision} asks whether anything moved. Three blocks of tests answer it: the feature tests, a $\chi^2$ test on the predicted labels and the MMD test. All of them form one family, tested at level $\alpha$ by a weighted Holm procedure \cite{holm1979}. The three blocks get equal weight and the feature block splits its weight equally over its features. A rejected test passes its weight on to the tests that remain. This controls the family wise error rate over every label free decision. The first step equals the Holm procedure over the three blocks, with each block's features pooled by their Bonferroni p value. Pooling lets the MMD test, whose smallest possible p value is $1/(B+1)$, compete with many feature tests. If no test rejects, the label free stage reports no shift.

If a block rejects, the diagnosis asks whether a change of the class balance alone explains the shift. BBSE estimates the new class prior. Let $C_{jk}=P(\hat y=j,y=k)$ on the calibration part and let $\mu_j$ be the share of production predictions in class $j$. The class weights $w$ are given by the solution of
\begin{equation}
C\,w = \mu, \qquad w_k = Q(Y=k)/P(Y=k).
\label{eq:bbse}
\end{equation}
Under a pure prior shift the inputs within each class keep their distribution. Reweighting each reference row by $w_{y}$ must then reproduce the production inputs. This label shift consistency test follows the prevalence adjustment of Roschewitz et al. \cite{roschewitz2025shiftid}. The feature tests are repeated against the reweighted reference, with Kish's effective sample size \cite{kish1965} and Holm correction. A feature that still differs carries a covariate shift. If none differs and the predicted labels moved, the shift is a prior shift. A prior shift always moves the predicted labels of an informative classifier, so a shift without that move is called covariate.

\paragraph{Audit stage.} Concept drift and label noise leave the inputs and the model outputs unchanged. Only labels can reveal them, so the audit draws $m$ late labels. A one sided two proportion test first asks whether accuracy fell. If it did, the diagnosis asks whether the change in errors depends on a feature. A logistic model of whether a prediction is correct is fitted on the calibration rows and the audit rows together. Its null form holds \res{const-quantile-bins} confidence bins at reference quantiles, bins of a feature $f$, an audit indicator and the interaction of that indicator with the confidence bins. The alternative adds the interaction of the audit indicator with the bins of $f$. A likelihood ratio test compares the two for each feature. A nominal category gets its own bin only if it occurs at least $n_{\min}$ times in the audit, where $n_{\min}$ is given by $\lceil 5/\min(e,1-e)\rceil$ and $e$ is the audit error rate. The other categories share one bin.

The confidence term is what separates the two types. In a binary task, uniform label noise at rate $r$ changes the probability of a correct prediction, which is then given by $r+(1-2r)P(\mathrm{correct}\mid x)$. The change depends on $x$ only through the model's own probability of being right, which the confidence bins of the null absorb. Concept drift moves the errors in a region of some feature. A feature significant after Holm correction therefore means concept drift and no significant feature means label noise. Each of the two stages is tested at level $\alpha$, so a window without drift gets a drift verdict with probability at most $2\alpha$.

\subsection{Root cause analysis}
The type tells a team what to do. The root cause analysis tells it where to look. It asks which inputs the model's decisions depend on differently after the shift. It narrows the search but does not prove a cause. For tabular models it computes SHAP values \cite{lundberg2017unified} of the deployed model with its preprocessing. It compares the mean absolute attribution of each feature between reference and production rows. Each change carries a percentile bootstrap interval whose level is Bonferroni adjusted over the features. For images, CAM shows which regions of an image support the prediction of the linear head \cite{zhou2016cam}. SHAP is reported for the logistic model only, since for the boosted model the exact explainer would take hours per window.

\subsection{Reliability and remediation triage}
The tests so far describe a whole window. Two practical questions remain: which single predictions deserve less trust and whether a cheap retrain would recover the loss. For the first, each prediction receives three signals in $[0,1]$: the confidence risk $1-c$, an OOD score and its instability under small input noise. The OOD score combines an Isolation Forest \cite{liu2008isolation} with a standardized distance. A logistic regression fitted on the calibration part combines them into a probability of error. It is fitted only when the calibration part holds at least ten wrong predictions per signal \cite{peduzzi1996}. Otherwise the risk is $1-c$ alone.

For the second, the triage predicts without production labels whether a cheap retrain will help. A classifier that tells reference rows from production rows gives density ratio weights, fitted on separate folds and truncated at \res{const-weight-clip} times their mean \cite{cortes2010weights}. A model trained with the weights is compared with an unweighted one on a held out \res{const-triage-valfrac}\% of the reference, itself weighted by the density ratio \cite{shimodaira2000,sugiyama2007}. When late labels from an earlier window exist, a second probe retrains on them and is validated on a held out part of that window. A retrain is recommended when a probe's predicted gain is significant after Holm correction across probes.

\section{Experimental setup}
\label{sec:setup}

The experiments answer two questions. Does the procedure name the type when the truth is known, including for drift it was not built around? And does it behave sensibly on real drift, where the type is unknown but the causes are documented?

\paragraph{Protocol.} Every setting below was fixed before the evaluation it is used in. The diagnosis and design B were both fixed before design B was first run. A later code review found two errors in the diagnosis. The label free stage had used a gatekeeping rule whose family wise error rate reached \res{fwer-gate-pct}\% at a nominal \res{fwer-alpha-pct}\% in a simulation, against \res{fwer-wholm-pct}\% for the weighted Holm procedure above. The audit had also counted nominal categories over the reference and audit rows together. Both errors were corrected without regard to the results and every result was regenerated. The correction changed the verdict in \res{fix-nchanged} of the \res{fix-nwindows} benchmark windows. Permutation tests use \res{acs-mmd-perm} permutations, SHAP explains \res{acs-shap-n} rows per side against \res{acs-shap-bg} background rows and the real audits use \res{acs-audit-n} labels from a random stream of their own for each window. All randomness is seeded, so results repeat exactly. One workstation with a \res{const-cpu-cores} core processor and a graphics processor ran everything. The graphics processor ran the image embeddings, the permutation tests and the large audit fits in double precision, with p values identical to the processor code. The software was scikit-learn \cite{pedregosa2011scikit}, SciPy, NumPy, SHAP, OpenCLIP and PyTorch. All code and outputs are available\ifanonymous{} (link withheld for review)\else{} in the project repository\fi.

\subsection{Models}
The procedure should not depend on one kind of model, so the same pipeline monitors two untuned model families. The first is logistic regression (LR) with $L_2$ regularization ($C=1$) on standardized numeric and one hot encoded nominal features. The second is histogram gradient boosting (GB) \cite{ke2017lightgbm} from scikit-learn \cite{pedregosa2011scikit}, with default settings, no early stopping and native splits on nominal codes. Codes beyond the 254 most frequent are pooled, which is the limit of the implementation. For CLEAR-10 both models act on the frozen embeddings.

\textbf{ACS Income and ACS Employment.} Both tasks come from the ACS of the United States Census Bureau, as packaged by Folktables \cite{ding2021retiring}. \textbf{Gas sensor array drift.} This dataset from the University of California, Irvine (UCI) machine learning repository holds 13{,}910 measurements of six gases by 16 metal oxide sensors over 36 months, in ten batches \cite{vergara2012gas,rodriguezlujan2014gas}. Each measurement has eight features per sensor. The sensors age, so their response to the same gas drifts while the labels stay exact. This is a documented change in $P(X\mid Y)$. Batches 1 and 2 form the reference and batches 3 to 10 the windows. Some batches are small, so the number of audit labels for a window of $n$ rows is given by $\min(600,\lfloor n/2\rfloor)$.

\textbf{CLEAR-10.} This image stream holds ten object classes and a background class in ten time ordered buckets of about 3{,}300 images each \cite{lin2021clear}. Bucket 1 is the reference.

\subsection{Injection benchmark}
\label{sec:benchmark-setup}
Real drift has no known type, so the diagnosis is graded on injected drift. The benchmark uses the 2014 data of \res{bench-nstates} states (\res{bench-states}) for both ACS tasks. Each state is a reference distribution with its own model, split as above. For each of \res{bench-nseeds} seeds the split, the window and the injection are redrawn. This gives \res{bench-nreps} replicates per configuration. Each replicate draws a production window of \res{bench-prodsize} rows and a grading holdout of \res{bench-holdsize} rows from the test part. Each mechanism is injected into both at three intensities.

\textbf{Design A} injects the four types in ways that partly match the tests. Covariate shift rescales two numeric features (ACS Income: \res{bench-cov-features-inc}) for a random subset of rows. Prior shift drops rows of one class until the positive rate rises by \res{bench-prior-steps}. Concept drift inverts the labels of the \res{bench-concept-steps}\% of rows with the highest value of one feature (ACS Income: \res{bench-concept-feature-inc}). Label noise flips a random \res{bench-noise-steps}\% of labels. A control window without drift completes each replicate.

\textbf{Design B} uses mechanisms that the tests were not built around. Covariate shift is selection bias. Each row is kept with a probability given by $\sigma(\beta s(x))$, where $\sigma$ is the logistic function, $s$ is a seeded random score over all inputs and $\beta\in\{\res{bench-b-betas}\}$. The rows stay real and $P(Y\mid X)$ is exactly unchanged. Prior shift lowers the positive rate by \res{bench-b-prior-steps}. Concept drift inverts the labels in the top \res{bench-b-concept-steps}\% of a second random score. This region is oblique: no single feature defines it. For ACS Income a second concept drift raises the income threshold to \res{bench-b-thresholds}. Label noise is class conditional, with positive labels flipped to negative at rates of \res{bench-b-noise-steps}\%.

The audit uses \res{bench-audit-n} labels. Proportions carry Wilson intervals \cite{wilson1927} and means carry bootstrap intervals over replicates.

\subsection{Baselines and ablations}
\label{sec:baselines}
A diagnosis is worth its cost only if it beats simpler options. Every method names one of the five outcomes (no drift or one of the four types) from the same test results and the same audit labels. Three rules represent current practice. \emph{Input monitoring} reads any input alarm as covariate shift, which is how drift alarms are commonly read. \emph{BBSE first} reads a shift of the predicted labels as prior shift \cite{lipton2018bbse,rabanser2019failing} and any other alarm as covariate shift. It is our label free stage without the consistency test. \emph{Error rate monitoring} adds a significant audit accuracy drop, read as concept drift, as an error rate detector would \cite{gama2004ddm}.

The \emph{learned meta classifier} tests whether a learned rule can replace the tests. It is a GB model on nine statistics of each window: the evidence $-\log_{10}p$ of each block test, the share of features with residual shift, the BBSE prior change, the CBPE change, the evidence and size of the audit accuracy drop and the evidence of the error structure test. In design A it is validated by leaving one state out. In design B it is trained on design A, again leaving out the predicted state, so it never sees a held out mechanism. Three ablations remove the MMD block, remove the confidence term of the audit null or replace the confidence bins by cells of predicted class and confidence.

Our procedure is compared with each other method by the per replicate difference in the share of correctly typed windows. A sign flip permutation test with \res{bench-nflips} flips gives the p value and Holm correction runs over the comparisons. Replicates are the unit, since the windows of one replicate share a model and a reference.

\keep{6}\subsection{Real drift}
\label{sec:res-real}
Real drift has no known type, but its causes are documented. The question here is whether the verdicts agree with those causes and whether the control windows stay quiet.

The datasets differ in how much the drift costs. On ACS Employment every window is diagnosed as covariate shift, yet accuracy changes by at most \res{emp-dacc-maxabs} points with LR. The inputs move, including relationship in 2019 and race from 2021, but the model is barely affected. A drift alarm alone would overstate the problem, which the accuracy estimate and the audit put in proportion. Every gas sensor batch is diagnosed as covariate shift. With LR, accuracy changes by \res{gas-b8-dacc} points in batch 8. This matches the known cause. The sensors age, so $P(X\mid Y)$ changes. The shift is not explained by the changing mix of gases. BBSE first calls every one of these batches a prior shift, because the predicted labels move as well. The consistency test prevents that mistake: the predictions move because the sensors read differently, not because the mix of gases changed.

\subsection{Reliability and triage}
\label{sec:res-reliability}
The last two stages score single predictions and advise on retraining.

The fused risk score is judged by how well it ranks wrong predictions. Where the fusion is learned, on ACS and CLEAR-10, its area under the receiver operating characteristic curve (AUROC) differs from that of confidence alone by \res{rel-other-diff-min} to \res{rel-other-diff-max} over \res{rel-other-n} windows and by \res{rel-bench-gain-min} to \res{rel-bench-gain-max} on the benchmark. On the gas sensor array the calibration part holds too few wrong predictions (\res{rel-gas-lr-cal-errors} with LR and \res{rel-gas-hgb-cal-errors} with GB) and the risk falls back to confidence. Confidence already says most of what can be said about a single prediction.

For the triage, a retrain truly helps when retraining with importance weights or on the latest labelled window significantly raises holdout accuracy. Over \res{rem-n} real settings, the triage is right in \res{rem-recent-correct} of the \res{rem-recent-n} settings that have an earlier labelled window, because its recent window probe is validated on real labels. Without such a window it relies on importance weighted validation. It is then right in \res{rem-norecent-correct} of \res{rem-norecent-n} settings, but mostly by holding, since a retrain truly helped in only \res{rem-norecent-helps} of them. On the benchmark its recall is \res{b-inc-a-lr-triage-recall}\%, because importance weighted validation cannot see gains made outside the reference data. A triage is only as good as the evidence it can validate on.

\section{Discussion}
\label{sec:discussion}

The results support the central claim. A diagnosis built from tests of the definitions of the drift types transfers to drift it was not designed for, while a rule learned from examples does not. The price is a small audit of late labels, needed only for concept drift and label noise.

Several limits qualify these results. Each benchmark window holds one type, while real windows such as ACS Income 2023 mix several. The four types are also an idealization. Sensor aging changes $P(X\mid Y)$ and through it $P(Y\mid X)$. Our procedure reports the resulting input shift as covariate. Design B reduces, but cannot remove, the risk that the benchmark favours the tests. The weighted residual tests ignore the sampling error of the BBSE weights. With hundreds of thousands of rows small shifts are significant, so effect sizes are reported next to every decision. Deep models trained end to end, text and streaming data are not covered.

\section{Conclusions}
\label{sec:conclusion}

We showed that the type of drift, which decides the response, can be named by hypothesis tests with a stated error rate from label free tests and a few hundred late labels. On injected drift it clearly beats rules from monitoring practice and the label shift literature. A learned meta classifier wins on the drift it was trained on but not on held out drift. It works unchanged for both model families. On real drift it reported no drift on every control window and traced documented events, from new occupation codes and a redesigned survey question to new coding of race answers and aging sensors.

Drift that does not reduce accuracy passes the audit unnoticed and class conditional label noise is often read as concept drift. Future work will condition the audit on the full model output, account for the sampling error of the label shift weights and test mixed drift.
