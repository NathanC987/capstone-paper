\begin{abstract}
A drift alarm reports that production data have changed. The appropriate response, however, depends on the type of change, which current monitoring tools rarely identify. We present an open monitoring pipeline built around a procedure that names four drift types with a stated error rate. Established label-free tests distinguish covariate shift from prior shift, while a new test on a few hundred late labels distinguishes concept drift from label noise. On injected drift in two census tasks and two model families, the procedure identifies the type in \res{bench-a-ours-min} to \res{bench-a-ours-max}\% of windows and outperforms rules used in monitoring practice. A learned classifier does better on the drift it was trained on but reaches only \res{bench-b-meta-min} to \res{bench-b-meta-max}\% on held-out drift mechanisms, where our tests retain \res{bench-b-ours-min} to \res{bench-b-ours-max}\%. On four real datasets with documented changes, the pipeline reported no drift on any control window and traced the known events.
\end{abstract}

\keywords{data drift, concept drift, label shift, label noise, model monitoring, hypothesis testing, drift diagnosis}

\section{Introduction}
\label{sec:intro}

A deployed classifier can lose accuracy quietly as production data move away from the data it was trained on, often long before reliable labels reveal the loss \cite{rabanser2019failing}. Existing monitors are good at announcing that a distribution has changed \cite{rabanser2019failing} and at estimating how much accuracy has been lost \cite{garg2022atc,kivimaki2025performance}. They rarely report what kind of change occurred, although each kind of drift calls for a different response.

The literature distinguishes three types of dataset shift \cite{moreno2012unifying}. Under covariate shift the inputs move while the rule linking inputs to labels stays the same, so reweighting the training data can help. Under prior shift only the class balance changes and recalibrating the model is usually enough. Concept drift alters the rule itself and needs fresh labels. We add label noise as a fourth type. It corrupts the labels used to judge the model and points to the labelling process rather than to the model.

Naming the type turns out to be harder than detecting a change. Covariate and prior shift both move the inputs and the predictions, whereas concept drift and label noise leave the inputs untouched and are therefore invisible to any label-free test.

We identify the type with a short sequence of hypothesis tests run at one significance level, with the family-wise error rate controlled. The first stage needs no labels and builds on established methods. It tests the inputs and the predictions for a shift, estimates the new class balance with black-box shift estimation (BBSE) \cite{lipton2018bbse} and, following Roschewitz et al. \cite{roschewitz2025shiftid}, asks whether this balance alone explains the shift in the inputs (prior shift) or not (covariate shift). The second stage is new. Using a few hundred late labels, it asks whether accuracy has fallen and, if so, whether the errors have changed in a way that depends on some input feature. Uniform label noise changes the error rate only according to how confident the model is, whereas concept drift changes it within one region of the input space. Since every step is a formal test, the false alarm rate is fixed in advance.

The contributions are as follows.
\begin{enumerate}
\item An audit test that separates concept drift from label noise using only a few hundred late labels. Existing shift tests, such as DetectShift \cite{maiapolo2023detectshift}, either require labelled production data or ignore label noise.
\item A hierarchical procedure that combines this audit with a label-free stage and names four drift types under family-wise error control.
\item A benchmark covering two tabular tasks and two model families, with matched as well as held-out drift mechanisms. It shows that tests built on the definitions of the types transfer to new drift, whereas a learned rule does not.
\item An open end-to-end monitoring pipeline that covers detection, accuracy estimation, root cause analysis, diagnosis, reliability scoring and remediation triage, evaluated on four real drifts with documented causes.
\end{enumerate}

\paragraph{Drift types.} Moreno-Torres et al. define covariate shift, prior shift and concept shift according to which part of the joint distribution of inputs and labels changes \cite{moreno2012unifying}. DetectShift tests for a shift in this joint distribution and in each of its parts, $P(X)$, $P(Y)$, $P(X\mid Y)$ and $P(Y\mid X)$ \cite{maiapolo2023detectshift}. However, it requires labels for the new data, a limitation its authors acknowledge. We adopt the same definitions, add label noise as a fourth type and require labels only for a small audit.

\paragraph{Drift detection.} Detectors that track the error rate, such as the drift detection method (DDM) \cite{gama2004ddm}, need a label for every prediction. They can detect concept drift but cannot distinguish it from label noise. Label-free detectors instead compare the inputs or the model outputs. Rabanser et al. compared univariate tests, kernel tests \cite{gretton2012kernel}, classifier two-sample tests \cite{lopezpaz2017c2st} and BBSD applied to the model outputs. They found that BBSD worked best overall \cite{rabanser2019failing}. All of them indicate that a shift has occurred but not of which type. Our pipeline uses such tests as building blocks and goes on to name the type.

\paragraph{Label shift.} BBSE recovers the new class prior from the confusion matrix of any classifier \cite{lipton2018bbse}. It assumes that the inputs within each class do not change, which is precisely the assumption that separates prior shift from covariate shift. Roschewitz et al. test this assumption on medical images. They resample the reference data to the estimated prevalence and attribute the shift to prevalence if the features then no longer differ \cite{roschewitz2025shiftid}. Our label-free stage builds on the same idea but uses importance weights instead of resampling and places every label-free decision in one family with a stated error rate.

\paragraph{Performance estimation without labels.} Average confidence (AC) \cite{hendrycks2017baseline}, difference of confidences (DoC) \cite{guillory2021predicting}, average thresholded confidence (ATC) \cite{garg2022atc} and CBPE \cite{kivimaki2025performance} all estimate accuracy from model outputs. Each assumes that the relationship between confidence and accuracy carries over to production. Because models often remain confident as their accuracy falls under shift \cite{ovadia2019trust}, this assumption can fail. Our pipeline reports CBPE alongside the other three and treats it as an upper bound when the assumption breaks.

\paragraph{Explanation, reliability and benchmarks.} Shapley additive explanations (SHAP) \cite{lundberg2017unified} and class activation maps (CAM) \cite{zhou2016cam} attribute predictions to features or to image regions. Out-of-distribution (OOD) scores such as the Isolation Forest \cite{liu2008isolation} flag unusual inputs, while importance weighting corrects covariate shift \cite{shimodaira2000,sugiyama2007,cortes2010weights}. Folktables \cite{ding2021retiring} and CLEAR \cite{lin2021clear} provide real shifts, although the type of each shift is unknown. Injected shifts supply a ground truth \cite{rabanser2019failing} but risk favouring the method under test. Each of these tools is used in one stage of our pipeline. Our benchmark holds out drift mechanisms to limit that risk.

Each prior method thus addresses part of the problem. To our knowledge, no published method separates concept drift from label noise with a small label audit. Nor has any type diagnosis been evaluated on drift mechanisms held out from its design.

\section{Method}
\label{sec:method}

The pipeline is designed for a team that has a deployed model, the labelled data on which it was built and a stream of unlabelled production data. Nothing else is required, although a few hundred late labels sharpen the diagnosis once they arrive. Below we define the four drift types and then follow the data through the pipeline.

Stages A to C bring the data into a common form, test whether anything has changed and estimate how much accuracy the change may cost. Stage D, the core of this paper, names the type of change and points to its likely cause. Stages E and F turn these findings into action for individual predictions and for the retraining decision. Only the optional audit in stage D uses production labels. Apart from the population stability index (PSI), which alarms at its conventional threshold, every decision is a hypothesis test at the significance level $\alpha=\res{acs-alpha}$. The family-wise error rate is controlled by the Holm procedure \cite{holm1979}, its weighted form or its Bonferroni bound.

\subsection{Notation and drift types}
\label{sec:types}
The tests described below require a precise statement of what each type of drift changes. The reference data are drawn from a distribution $P(X,Y)$ over inputs $X$ and labels $Y$. A production window is a batch of rows from a later period or a different region, drawn from $Q(X,Y)$. The model returns a predicted label $\hat y$ and a confidence $c$, its largest class probability. The four types differ in what changes between $P$ and $Q$. Covariate shift has $Q(X)\neq P(X)$ while $Q(Y\mid X)=P(Y\mid X)$. Prior shift has $Q(Y)\neq P(Y)$ while $Q(X\mid Y)=P(X\mid Y)$. Concept drift has $Q(Y\mid X)\neq P(Y\mid X)$. Under label noise the true distribution stays the same, but each observed label differs from the true one with some probability. An audit is a random sample of $m$ production rows whose labels arrive late. A control window is drawn from the reference distribution itself and should therefore raise no alarm. Real drift can mix several types, as Section~\ref{sec:discussion} discusses.

\subsection{Reference split, detection and estimation}
This stage addresses three questions in turn: whether the data have moved, how much accuracy the change might cost and where it is located. It first requires a clean reference. The labelled reference data are split into three disjoint parts, stratified by class: \res{acs-split-pct-train}\% for training, \res{acs-split-pct-calibration}\% for calibration and \res{acs-split-pct-test}\% for testing. The model is fitted on the training part alone. The calibration part is the reference window for every detector and fits the accuracy estimator, while the test part gives the reference accuracy and acts as the control window. Nominal features, such as an occupation code, are treated as categorical because their numeric order carries no meaning. Images are mapped to the \res{clear-dim}-dimensional output of the global average pooling layer of a frozen residual network with 18 layers (ResNet-18) trained on ImageNet \cite{he2016deep}, so image drift can be tested with the tabular tests \cite{rabanser2019failing}.

Six detectors decide whether the inputs or the model outputs have moved. The Kolmogorov--Smirnov (KS) test is applied to each numeric feature with a Bonferroni correction. PSI alarms at the conventional value of \res{acs-psi-threshold} \cite{siddiqi2006}. The maximum mean discrepancy (MMD) test \cite{gretton2012kernel} is a permutation test on all standardized inputs jointly, using a Gaussian kernel. The confidence test compares histograms of $c$ with a $\chi^2$ test of homogeneity, pooling sparse cells until every expected count reaches \res{const-min-expected} \cite{cochran1954}. Two detectors from Rabanser et al. serve as baselines \cite{rabanser2019failing}. BBSD applies a KS test to each class probability. The domain classifier trains gradient boosted trees to separate \res{acs-dc-n} reference rows from as many production rows and compares its held-out accuracy with $1/2$ by an exact binomial test \cite{lopezpaz2017c2st}. Every permutation p value is given by $(1+b)/(1+B)$, where $b$ of the $B$ permutations reach the observed statistic \cite{phipson2010}.

Because labels arrive late, accuracy is first estimated from the model's own confidence with CBPE \cite{kivimaki2025performance}. A map $a(\cdot)$ from confidence to the probability of a correct prediction is fitted by histogram binning on the calibration part. The estimate for a window with confidences $c_1,\dots,c_n$ is given by
\begin{equation}
\widehat{\mathrm{acc}} = \frac{1}{n}\sum_{i=1}^{n} a(c_i).
\label{eq:cbpe}
\end{equation}
A confidence bin with fewer than \res{const-min-expected} calibration rows gives no reliable accuracy, so predictions in such a bin keep their own confidence. AC, DoC and ATC (with the negative entropy score) are fitted on the same calibration part as baselines \cite{hendrycks2017baseline,guillory2021predicting,garg2022atc}.

An alarm is more useful when it also says where the change is located. Localization tests every feature with KS (numeric) or $\chi^2$ homogeneity (nominal) under Holm correction and reports an effect size in $[0,1]$, the KS statistic or Cram\'er's $V$. For nominal features it also reports the share of production rows whose category never occurs in the reference.

\paragraph{Label-free stage.} The first question in Figure~\ref{fig:decision} is whether anything has moved at all. Three blocks of tests answer it: the feature tests, a $\chi^2$ test on the predicted labels and the MMD test. They form one family, tested at level $\alpha$ with a weighted Holm procedure \cite{holm1979}. The three blocks receive equal weight, which the feature block divides equally among its features. Whenever a test is rejected, its weight passes to the tests that remain, so the family-wise error rate is controlled over every label-free decision. The first step equals the Holm procedure over the three blocks, with each block's features pooled by their Bonferroni p value. Pooling lets the MMD test, whose smallest possible p value is $1/(B+1)$, compete with many feature tests. If no test rejects, the label-free stage reports no shift.

If a block rejects, the diagnosis asks whether a change in the class balance alone explains the shift. BBSE estimates the new class prior. Let $C_{jk}=P(\hat y=j,y=k)$ on the calibration part and let $\mu_j$ be the share of production predictions in class $j$. The class weights $w$ are given by the solution of
\begin{equation}
C\,w = \mu, \qquad w_k = Q(Y=k)/P(Y=k).
\label{eq:bbse}
\end{equation}
Under a pure prior shift the inputs within each class keep their distribution, so reweighting each reference row by $w_{y}$ should reproduce the production inputs. This label shift consistency test follows the prevalence adjustment of Roschewitz et al. \cite{roschewitz2025shiftid}. The feature tests are repeated against the reweighted reference with Kish's effective sample size \cite{kish1965} and Holm correction. Any feature that still differs carries a covariate shift. If none differs and the predicted labels have moved, the shift is a prior shift. A prior shift always moves the predicted labels of an informative classifier, so a shift without such a move is called covariate.

\paragraph{Audit stage.} Concept drift and label noise leave the inputs and the model outputs unchanged, so only labels can reveal them. The audit draws $m$ late labels and first checks with a one-sided two-proportion test whether accuracy has fallen. If it has, the diagnosis asks whether the change in errors depends on a feature. A logistic model of whether a prediction is correct is fitted on the calibration rows and the audit rows together. Its null form contains \res{const-quantile-bins} confidence bins at reference quantiles, bins of a feature $f$, an audit indicator and the interaction of that indicator with the confidence bins. The alternative adds the interaction of the audit indicator with the bins of $f$ and is compared with the null by a likelihood ratio test for each feature. A nominal category receives its own bin only if it occurs at least $n_{\min}$ times in the audit, where $n_{\min}$ is given by $\lceil 5/\min(e,1-e)\rceil$ and $e$ is the audit error rate. The remaining categories share one bin.

It is the confidence term that separates the two types. In a binary task, uniform label noise at rate $r$ changes the probability of a correct prediction, which is then given by $r+(1-2r)P(\mathrm{correct}\mid x)$. The change depends on $x$ only through the model's own probability of being right, which the confidence bins of the null absorb. Concept drift instead shifts the errors within a region of some feature. A feature that remains significant after Holm correction therefore indicates concept drift, whereas no significant feature indicates label noise. Because each of the two stages is tested at level $\alpha$, a window without drift receives a drift verdict with probability at most $2\alpha$.

\subsection{Root cause analysis}
Knowing the type tells a team what to do, while root cause analysis tells it where to look. This stage asks which inputs the model's decisions depend on differently after the shift. It narrows the search but does not prove a cause. For tabular models we compute SHAP values \cite{lundberg2017unified} of the deployed model with its preprocessing and compare the mean absolute attribution of each feature between reference and production rows, each change with a percentile bootstrap interval whose level is Bonferroni adjusted over the features. For images, CAM shows which image regions support the prediction of the linear head \cite{zhou2016cam}. SHAP is reported for the logistic model only, because for the boosted model the exact explainer would take hours per window.

\subsection{Reliability and remediation triage}
The tests so far describe a window as a whole. Two practical questions remain: which individual predictions deserve less trust and whether a cheap retrain would recover the lost accuracy. For the first, each prediction receives three signals in $[0,1]$: the confidence risk $1-c$, an OOD score and its instability under small input perturbations. The OOD score combines an Isolation Forest \cite{liu2008isolation} with a standardized distance. A logistic regression fitted on the calibration part combines them into a probability of error. It is fitted only when the calibration part holds at least ten wrong predictions per signal \cite{peduzzi1996}; otherwise the risk is simply $1-c$.

For the second, the triage predicts without production labels whether a cheap retrain will help. A classifier that separates reference from production rows provides density ratio weights, fitted on separate folds and truncated at \res{const-weight-clip} times their mean \cite{cortes2010weights}. A model trained with these weights is compared with an unweighted one on a held-out \res{const-triage-valfrac}\% of the reference, itself weighted by the density ratio \cite{shimodaira2000,sugiyama2007}. When late labels from an earlier window are available, a second probe retrains on them and is validated on a held-out part of that window. A retrain is recommended when a probe's predicted gain is significant after Holm correction across probes.

\section{Experimental setup}
\label{sec:setup}

The experiments answer two questions. Does the procedure name the type correctly when the truth is known, including for drift it was not designed for? And does it behave sensibly on real drift, where the type is unknown but the causes are documented?

\paragraph{Protocol.} All settings below were fixed before the evaluation that uses them. The diagnosis and design B were both fixed before design B was first run. A later code review uncovered two errors in the diagnosis. The label-free stage had used a gatekeeping rule whose family-wise error rate reached \res{fwer-gate-pct}\% at a nominal \res{fwer-alpha-pct}\% in a simulation, compared with \res{fwer-wholm-pct}\% for the weighted Holm procedure described above. The audit had also counted nominal categories over the reference and audit rows together. Both were corrected without regard to the results and every result was regenerated, which changed the verdict in \res{fix-nchanged} of the \res{fix-nwindows} benchmark windows. Permutation tests use \res{acs-mmd-perm} permutations, SHAP explains \res{acs-shap-n} rows per side against \res{acs-shap-bg} background rows and each real audit uses \res{acs-audit-n} labels from its own random stream. All randomness is seeded, so results repeat exactly. One workstation with a \res{const-cpu-cores}-core processor and a graphics processor ran everything. The graphics processor computed the embeddings, permutation tests and large audit fits in double precision, with p values identical to the processor code. The software was scikit-learn \cite{pedregosa2011scikit}, SciPy, NumPy, SHAP, OpenCLIP and PyTorch. All code and outputs are available\ifanonymous{} (link withheld for review)\else{} in the project repository\fi.

\subsection{Models}
Since the procedure should not depend on one kind of model, the same pipeline monitors two untuned model families. The first is logistic regression (LR) with $L_2$ regularization ($C=1$) on standardized numeric and one-hot encoded nominal features. The second is histogram gradient boosting (GB) \cite{ke2017lightgbm} from scikit-learn \cite{pedregosa2011scikit} with default settings, no early stopping and native splits on nominal codes. Codes beyond the 254 most frequent are pooled, which is the limit of the implementation. For CLEAR-10 both models operate on the frozen embeddings.

In 2019 the relationship variable RELP was replaced by RELSHIPP \cite{census2019pums}, which we map back to RELP using the code labels of the 2018 and 2019 data dictionaries. Five documented changes fall within these years: new occupation codes in 2018 \cite{census2020occupation}, a redesigned relationship question in 2019, a new coding of race answers from 2020 \cite{census2021race}, the pandemic and wage growth against the fixed income threshold.

\textbf{Gas sensor array drift.} This dataset from the University of California, Irvine (UCI) machine learning repository holds 13{,}910 measurements of six gases by 16 metal oxide sensors over 36 months, in ten batches \cite{vergara2012gas,rodriguezlujan2014gas}. Each measurement has eight features per sensor. As the sensors age, their response to the same gas drifts while the labels stay exact, a documented change in $P(X\mid Y)$. Batches 1 and 2 form the reference and batches 3 to 10 the windows. Because some batches are small, the number of audit labels for a window of $n$ rows is given by $\min(600,\lfloor n/2\rfloor)$.

\textbf{CLEAR-10.} This image stream holds ten object classes and a background class in ten time-ordered buckets of about 3{,}300 images each \cite{lin2021clear}. Bucket 1 serves as the reference.

\subsection{Injection benchmark}
\label{sec:benchmark-setup}
Real drift has no known type, so the diagnosis is graded on injected drift. The benchmark uses the 2014 data of \res{bench-nstates} states (\res{bench-states}) for both ACS tasks. Each state is a reference distribution with its own model, split as above. For each of \res{bench-nseeds} seeds the split, the window and the injection are redrawn, which gives \res{bench-nreps} replicates per configuration. Each replicate draws a production window of \res{bench-prodsize} rows and a grading holdout of \res{bench-holdsize} rows from the test part. Each mechanism is injected into both at three intensities. The audit uses \res{bench-audit-n} labels. Proportions carry Wilson intervals \cite{wilson1927} and means carry bootstrap intervals over replicates.

\textbf{Design A} injects the four types in ways that partly match the tests. Covariate shift rescales two numeric features (ACS Income: \res{bench-cov-features-inc}) for a random subset of rows. Prior shift drops rows of one class until the positive rate rises by \res{bench-prior-steps}. Concept drift inverts the labels of the \res{bench-concept-steps}\% of rows with the highest value of one feature (ACS Income: \res{bench-concept-feature-inc}). Label noise flips a random \res{bench-noise-steps}\% of labels. Each replicate also includes a control window without drift.

\textbf{Design B} uses mechanisms that the tests were not designed for. Covariate shift is selection bias: each row is kept with a probability given by $\sigma(\beta s(x))$, where $\sigma$ is the logistic function, $s$ is a seeded random score over all inputs and $\beta\in\{\res{bench-b-betas}\}$. The rows stay real and $P(Y\mid X)$ is exactly unchanged. Prior shift lowers the positive rate by \res{bench-b-prior-steps}. Concept drift inverts the labels in the top \res{bench-b-concept-steps}\% of a second random score, which defines an oblique region that no single feature describes. For ACS Income a second concept drift raises the income threshold to \res{bench-b-thresholds}. Label noise is class-conditional, with positive labels flipped to negative at rates of \res{bench-b-noise-steps}\%.
\subsection{Baselines and ablations}
\label{sec:baselines}
A diagnosis is only worth its cost if it beats simpler options. Every method names one of the five outcomes (no drift or one of the four types) from the same tests and audit labels. Three rules represent current practice. \emph{Input monitoring} reads any input alarm as covariate shift, which is how drift alarms are commonly read. \emph{BBSE first} reads a shift in the predicted labels as prior shift \cite{lipton2018bbse,rabanser2019failing} and any other alarm as covariate shift, which makes it our label-free stage without the consistency test. \emph{Error-rate monitoring} also reads a significant audit accuracy drop as concept drift, like an error-rate detector \cite{gama2004ddm}.

The \emph{learned meta-classifier} tests whether a learned rule could replace the tests. It is a GB model on nine statistics of each window: the evidence $-\log_{10}p$ of each block test, the share of features with residual shift, the BBSE prior change, the CBPE change, the evidence and size of the audit accuracy drop and the evidence of the error structure test. In design A it is validated by leaving one state out. In design B it is trained on design A without the predicted state, so it never sees a held-out mechanism. Three ablations remove the MMD block, remove the confidence term from the audit null or replace the confidence bins by cells of predicted class and confidence.

Our procedure is compared with each other method by the per-replicate difference in the share of correctly typed windows, tested by sign-flip permutation (\res{bench-nflips} flips) with Holm correction. Replicates are the unit of analysis because the windows of one replicate share a model and a reference.

\subsection{Reliability and triage}
\label{sec:res-reliability}
The last two stages score individual predictions and advise on retraining.

The fused risk score is judged by how well it ranks wrong predictions. Where the fusion is learned, on ACS and CLEAR-10, its area under the receiver operating characteristic curve (AUROC) differs from that of confidence alone by \res{rel-other-diff-min} to \res{rel-other-diff-max} over \res{rel-other-n} windows and by \res{rel-bench-gain-min} to \res{rel-bench-gain-max} on the benchmark. On the gas sensor array the calibration part contains too few wrong predictions (\res{rel-gas-lr-cal-errors} with LR and \res{rel-gas-hgb-cal-errors} with GB), so the risk falls back to confidence. Confidence alone already carries most of the information about a single prediction.

A retrain truly helps when retraining with importance weights or on the latest labelled window significantly raises holdout accuracy. Over \res{rem-n} real settings, the triage is right in \res{rem-recent-correct} of the \res{rem-recent-n} settings that have an earlier labelled window, because its recent-window probe is validated on real labels. Without one it relies on importance-weighted validation and is right in \res{rem-norecent-correct} of \res{rem-norecent-n} settings, but mostly by advising against retraining, since one truly helped in only \res{rem-norecent-helps} of them. On the benchmark its recall is \res{b-inc-a-lr-triage-recall}\%, because importance-weighted validation cannot see gains outside the reference data.

\section{Discussion}
\label{sec:discussion}

The results support the central claim. A diagnosis built from tests of the type definitions transfers to drift it was not designed for, whereas a learned rule does not. The cost is a small label audit, needed only for concept drift and label noise.

Several limitations qualify these findings. Each benchmark window contains a single type, while real windows such as ACS Income 2023 mix several. The four types are also an idealization: sensor aging changes $P(X\mid Y)$ and, through it, $P(Y\mid X)$, yet our procedure reports it as covariate shift. Design B reduces, but cannot eliminate, the risk that the benchmark favours the tests. The weighted residual tests also ignore the sampling error of the BBSE weights. With hundreds of thousands of rows even small shifts become significant, which is why effect sizes are reported next to every decision. Deep models trained end to end, text and streaming data are not covered.

\section{Conclusions}
\label{sec:conclusion}

We showed that the drift type, which determines the response, can be identified by hypothesis tests with a stated error rate from label-free tests and a few hundred late labels. On injected drift it outperforms rules from monitoring practice and the label shift literature, works for both model families and, unlike a learned meta-classifier, transfers to held-out drift. On real drift it reported no drift on any control window and traced documented events, from new occupation codes to aging sensors.

Drift that leaves accuracy intact passes the audit unnoticed, while class-conditional label noise is often read as concept drift. Future work will condition the audit on the full model output, model the sampling error of the BBSE weights and test mixed drift.
